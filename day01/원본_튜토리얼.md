# 1일차 실습 — 스프링 시큐리티 켜고, 막혀 보고, 필요한 만큼 열기

오늘 만들 것: 공지·내 정보·관리자 통계 API 3개를 가진 서버에 스프링 시큐리티를 붙여서
**공지는 누구나, 내 정보는 로그인한 사람만, 관리자 통계는 관리자만** 보이게 한다.

| 폴더 | 내용 |
|---|---|
| `backend-start/` | 시작 코드. 보안 없음 |
| `backend-final/` | 완성 코드. 막히면 비교한다 |
| `frontend/` | React 화면. 오늘은 수정하지 않는다 |

준비물: JDK 17, Node 22 이상, VS Code 또는 IntelliJ

---

## 0단계. 보안 없는 서버 실행하기

**할 일** 서버와 화면을 띄우고 세 버튼을 눌러 본다.

```bash
# 터미널 1 — 서버 (Windows 명령 프롬프트는 gradlew.bat)
cd backend-start
./gradlew bootRun

# 터미널 2 — 화면
cd frontend
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 연다. 아이디 칸은 비워 둔다.

**확인** 세 버튼 모두 상태 `200`. **관리자 통계까지 누구나 보인다.** 오늘 고칠 문제다.

**막히면**
- 처음 실행은 Gradle과 라이브러리를 내려받느라 몇 분 걸린다. `BUILD SUCCESSFUL`이 아니라 `Started SecurityDay1Application`이 보이면 서버가 뜬 것이다 (진행률이 80% 근처에서 멈춘 것처럼 보여도 정상)
- `JAVA_HOME is not set` → JDK 17 설치 후 터미널을 다시 연다
- `Port 8080 was already in use` → 다른 서버를 끈다. 이전 실습 서버가 켜져 있는 경우가 많다

## 1단계. 의존성 하나 추가하기

**할 일** `backend-start/build.gradle`의 `dependencies { }` 안에 두 줄을 추가하고 서버를 다시 시작한다.

```groovy
implementation 'org.springframework.boot:spring-boot-starter-security'
testImplementation 'org.springframework.security:spring-security-test'
```

**확인**
1. 서버 콘솔에 `Using generated security password: 8f3c...` 같은 줄이 보인다. 이 값을 복사해 둔다
2. 화면에서 **공개 공지까지** 세 버튼 모두 `요청 실패`가 뜬다
3. F12 → Console 탭에 `blocked by CORS policy`가 보인다
4. F12 → Network 탭에서 공개 공지 요청을 보면 `OPTIONS` 요청이 **401**이고, 그 뒤의 `GET` 요청은 **아예 없다**

> 공개 API인데 왜 실패할까? 답은 3단계에서 확인한다.

**막히면**
- 비밀번호 줄이 안 보인다 → 콘솔을 위로 올려 `generated` 로 검색한다
- IntelliJ에서 `build.gradle`을 고친 뒤 코끼리 아이콘(Load Gradle Changes)을 누르지 않으면 import가 빨갛게 보인다
- `backend-start`에서 `./gradlew test`를 돌리면 `ApiControllerTest`가 실패한다 → 정상이다. 이 테스트는 "보안이 없는 상태"를 검사하므로 1단계부터는 실패하는 것이 맞다

## 2단계. 기본 로그인 해보기

**할 일** 브라우저 주소창에 `http://localhost:8080/api/me`를 직접 입력한다.

**확인**
1. `http://localhost:8080/login`으로 이동하고 "Please sign in" 화면이 나온다
2. Username `user`, Password에 1단계에서 복사한 값을 넣으면 `{"username":"user"}`가 보인다
3. F12 → Application → Cookies에 `JSESSIONID`가 생겼다 (5일차에 다시 본다)

> 주소창에서 연 요청은 로그인 페이지로 보낸다. 반면 React처럼 API로 부르는 요청에는 로그인 페이지 대신 401을 돌려준다(3단계에서 화면으로 확인). 스프링 시큐리티가 **요청 헤더를 보고 화면용인지 API용인지 구분**하기 때문이다.

## 3단계. 보안 설정 클래스 만들기

**할 일** `src/main/java/com/kyobo/lab/SecurityConfig.java`를 새로 만든다.

```java
package com.kyobo.lab;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.core.userdetails.User;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.provisioning.InMemoryUserDetailsManager;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

	@Bean
	public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
		http
				.cors(Customizer.withDefaults())
				.authorizeHttpRequests(auth -> auth
						.requestMatchers("/api/public/**").permitAll()
						.anyRequest().authenticated())
				.httpBasic(Customizer.withDefaults())
				.formLogin(Customizer.withDefaults());
		return http.build();
	}

	@Bean
	public UserDetailsService userDetailsService() {
		return new InMemoryUserDetailsManager(
				User.withUsername("user").password("{noop}1234").roles("USER").build(),
				User.withUsername("admin").password("{noop}1234").roles("ADMIN").build());
	}
}
```

서버를 다시 시작한다.

**확인** 아이디 칸을 비우고
- 공개 공지 → `200`
- 내 정보 → `401` (이제 `요청 실패`가 아니라 401이 그대로 보인다)

서버 콘솔에 생성 비밀번호 줄이 **더 이상 나오지 않는다.** 사용자를 직접 등록했기 때문이다.

> **1단계의 답** — React는 다른 주소(3000 → 8080)로 헤더를 붙여 요청하기 전에, 브라우저가 먼저 **사전 요청(OPTIONS)** 으로 "보내도 되나요?"를 묻는다. 사전 요청에는 로그인 정보가 없어서 보안 필터가 401로 거절했고, CORS 허용 헤더도 없어서 브라우저는 진짜 GET을 보내지 않았다. `.cors(...)` 줄이 CORS 처리를 보안 검사보다 먼저 하게 만들어서 이 문제가 풀렸다.

**막히면**
- `There is no PasswordEncoder mapped for the id "null"` → 비밀번호 앞의 `{noop}`이 빠졌다
- 공개 공지는 200인데 내 정보가 401이 아니라 `요청 실패` → `.cors(Customizer.withDefaults())` 줄이 빠졌다
- 블로그 코드의 `extends WebSecurityConfigurerAdapter`, `antMatchers`, `.and()` → 스프링 시큐리티 5 이전 문법이다. 6에서는 위처럼 쓴다

## 4단계. React에서 로그인해서 호출하기

**할 일** 화면의 아이디 `user`, 비밀번호 `1234`를 입력하고 세 버튼을 누른다.

**확인**
- 내 정보 → `200`, `{"username":"user"}`
- 관리자 통계 → `200` ← **일반 사용자인데 관리자 통계가 보인다**

> `authenticated()`는 "로그인만 했으면 누구든"이라는 뜻이다. **인증(누구인가)** 과 **인가(무엇을 해도 되는가)** 는 다른 문제다.

비밀번호를 `9999`로 바꿔 내 정보를 누르면 `401`이다.

---

## 5단계. 관리자만 허용하기

**할 일** `SecurityConfig`의 `permitAll()` 줄 바로 아래에 한 줄을 추가하고 서버를 다시 시작한다.

```java
						.requestMatchers("/api/public/**").permitAll()
						.requestMatchers("/api/admin/**").hasRole("ADMIN")   // 추가
						.anyRequest().authenticated())
```

**확인**

| 아이디 | 관리자 통계 |
|---|---|
| (비움) | 401 |
| user / 1234 | **403** |
| admin / 1234 | 200 |

> 401은 "누군지 모르겠다", 403은 "누군지는 아는데 안 된다"다.

**막히면**
- `Can't configure mvcMatchers after anyRequest` → 추가한 줄이 `anyRequest()` 아래에 있다. 규칙은 **좁은 것부터 위에**, `anyRequest()`는 항상 마지막
- `ROLE_ADMIN should not start with ROLE_` → `hasRole`은 `ROLE_`을 자동으로 붙이므로 `hasRole("ADMIN")`으로 쓴다

## 6단계. 요청이 지나가는 필터 보기

**할 일** `src/main/resources/application.properties`에 추가하고 서버를 다시 시작한다.

```properties
logging.level.org.springframework.security=TRACE
```

**확인**
1. 시작 로그에서 `Will secure any request with filters:` 줄을 찾는다. 필터가 **16개** 나열된다
2. 화면에서 `user / 1234`로 관리자 통계를 누른 뒤 로그에서 아래 흐름을 찾는다. 바로 앞에 `Securing OPTIONS /api/admin/stats`(5/16에서 끝남)가 먼저 나오는데, 1단계에서 본 사전 요청이다. 그 다음의 `GET`을 본다

```
Securing GET /api/admin/stats
Invoking CorsFilter (5/16)
...
Invoking BasicAuthenticationFilter (11/16)
...
Invoking ExceptionTranslationFilter (15/16)
Invoking AuthorizationFilter (16/16)
```

3. 아래 표를 채운다

| 질문 | 내 답 |
|---|---|
| 아이디·비밀번호를 확인한 필터는? | |
| "권한 없음"을 판정한 필터는? | |
| 그 판정을 403 응답으로 바꾼 필터는? | |
| CORS를 처리한 필터는 몇 번째인가? 왜 앞에 있어야 할까? | |

<details>
<summary>정답 보기</summary>

1. `BasicAuthenticationFilter` (11/16)
2. `AuthorizationFilter` (16/16) — `hasRole("ADMIN")` 규칙으로 거절을 판정한다
3. `ExceptionTranslationFilter` (15/16) — 인증된 사용자의 거절이므로 403을 보낸다. 로그인하지 않았다면 401로 바꾼다
4. `CorsFilter` (5/16) — 사전 요청에는 로그인 정보가 없으므로, 인증 필터보다 먼저 처리하지 않으면 401로 막힌다

</details>

로그가 너무 많으면 확인 후 `TRACE`를 `DEBUG`로 바꾼다.
